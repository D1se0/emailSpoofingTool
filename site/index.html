¿Qué es MailForge?

Una suite defensiva anti-spoofing: audita qué tan fácil es suplantar un dominio de email y genera la configuración para evitarlo. Cubre SPF (RFC 7208), DKIM (RFC 6376), DMARC (RFC 7489), DNSSEC, MTA-STS (RFC 8460) y TLS-RPT. El core es Python stdlib puro: sin dependencias obligatorias, con cliente DNS propio y fallback a DNS-over-HTTPS.

💡 Dos webs, dos propósitos: esta página es documentación pública estática; la consola de testeo (analyzer, Spoof Lab, hardening) corre en local con npm start en server/ y habla con el motor real.

Uso legítimo

⚠ MailForge no es una herramienta de phishing. El análisis es 100% pasivo (DNS público) y nunca envía correos. Las dos funciones ofensivas-asistidas están cerradas:

✅ Spoof Lab: genera el mensaje de drill + comandos — tú lo inyectas desde tu relay hacia un buzón tuyo del dominio analizado.
✅ Self-test: un único email técnico a un buzón del dominio analizado.
❌ Ningún envío a terceros, ningún dominio ajeno, nunca.

Usarlo contra dominios que no controlas para algo distinto de una consulta DNS pública (que es lo que hace cualquier dig) viola la licencia de uso.

Spoof Lab — la perspectiva del atacante

El módulo que responde a la pregunta: "¿un atacante real conseguiría suplantarme?". Funciona en 3 pasos:

  1. Render — construye el email suplantado realista (From: "CEO (aviso urgente)" <ceo@tudominio>, Reply-To secuestrado, motivo de ingeniería social: factura, contraseña o bonus).
  2. Predicción — consulta tu postura DNS en vivo y predice el veredicto: INBOX = suplantable cuarentena RECHAZADO 550.
  3. Inyección (tú) — copia los comandos swaks/sendmail y lanza el drill desde tu relay hacia tu buzón. Observa: ¿inbox, spam o rechazo? Y revisa Authentication-Results y el informe rua del día.
⚠ El motor nunca se conecta al MX de destino para este drill: los comandos apuntan a un relay autorizado por ti. Es la misma filosofía de un pentest interno: el explotación la ejecuta el operador autorizado.

Modelo de scoring

score = 0.20·SPF + 0.10·DKIM + 0.40·DMARC + 0.10·DNSSEC + 0.10·TLS + 0.10·Extras
PilarPesoQué puntúa
DMARC40%política efectiva (p/sp), pct, alineación estricta, rua
SPF20%presencia, mecanismo all, errores, límite 10 lookups, ptr
DKIM10%claves activas, fuerza ≥2048 bits, revocadas, wildcards
DNSSEC10%DS en zona padre / AD bit / RRSIG
TLS10%STARTTLS real contra tus MX + MTA-STS + TLS-RPT
Extras10%MTA-STS, TLS-RPT, BIMI

Grados: A ≥ 85 · B ≥ 70 · C ≥ 50 · D ≥ 25 · F < 25.

Los 8 vectores de ataque

  1. Spoof directo — From desalineado con dominio propio del atacante (mitiga: DMARC).
  2. Spoof exacto — MAIL FROM en tu dominio desde IP ajena (mitiga: SPF -all).
  3. Lookalike — typosquat/homoglifo (mitiga: marca, BIMI, formación).
  4. Replay DKIM — reenvío de mensaje firmado (mitiga: reject, h= completo).
  5. Bounces nulos — abuso de MAIL FROM:<> (mitiga: alineación + reject).
  6. Escape por subdominio — sin política heredada (mitiga: sp=reject).
  7. Display-name — "CEO <atacante@evil>" (mitiga: BIMI, formación).
  8. Downgrade STARTTLS — MITM sin MTA-STS/DANE (mitiga: MTA-STS enforce).

SPF · DKIM · DMARC en 60 segundos

  • SPF autoriza qué servidores envían por tu dominio (MAIL FROM). Termina siempre en -all.
  • DKIM firma el correo; la clave pública vive en selector._domainkey.
  • DMARC exige que SPF o DKIM pasen y estén alineados con el From visible; define la acción al fallar y a dónde reportar.

Rollout DMARC por fases

FASE 0   p=none; rua=mailto:…        2-4 semanas: recopilar informes
FASE 1   p=quarantine; pct=25        25% de fallos a spam
FASE 2   p=quarantine; pct=100       si no hay falsos positivos
FASE 3   p=reject; sp=reject; adkim=s; aspf=s   estado final
FASE 4   + MTA-STS enforce + TLS-RPT + BIMI

FAQ

¿Puedo escanear cualquier dominio?

Sí: son consultas DNS públicas y pasivas, como dig. La ética dicta actuar (inyectar drills, hardening) solo sobre dominios propios.

¿Guardáis datos?

No. Todo es stateless, sin base de datos ni telemetría. La web pública ni siquiera tiene backend.

¿Por qué el Analyzer de la web pública no funciona?

Porque esta página es solo documentación (estática, en Pages). El análisis interactivo está en la consola local: cd server && npm start.

¿Funciona tras un firewall que bloquea el puerto 53?

Sí: el core cae automáticamente a DNS-over-HTTPS (dns.google / Cloudflare).

¿El Spoof Lab puede usarme a mí de víctima sin querer?

No: valida que el buzón destino sea del dominio analizado y los comandos requieren tu relay y tu acción explícita.
